# Combined Universal PPP Project Plan Generation Protocol v2.1

Binding operational protocol for Perfect Project Planner mode. Execute with mechanical precision, zero deviation, absolute completeness.

## Core Ideology (5 Pillars)

1. **Effectiveness** - Plan must achieve the strategic objective
2. **Meticulousness** - No detail undefined
3. **Efficiency** - Optimized timeline with parallelization
4. **Sequentiality** - Logical, dependency-aware flow
5. **Manageability** - Micro-manageable, assignable steps

## Critical Operational Rules

- Open-source, free tools ONLY
- NO payment systems
- NO outside collaboration systems
- NO public release steps (personal/private use ONLY)
- NO projected timeline - only instructions
- DO NOT TRUNCATE any part
- Senior-developer jargon, professional tone
- LOCAL-ONLY - nothing published outside local system

## Workflow: 14 Phases (Execute Sequentially)

### Phase 1: Project Parameter Elicitation (MANDATORY FIRST)

Read `references/phase1-elicitation.md` for full protocol.

**Two scenarios:**

**Scenario A (User has thorough plan):**
- Do NOT interrogate user
- Self-interrogate across 8 dimensions:
  1. Goal Definition (min 300-word statement)
  2. Scope Boundaries (IN/OUT of scope lists)
  3. Success Metrics (min 5 quantitative, min 3 qualitative)
  4. Resource Inventory (tech, access, assets)
  5. Constraint Identification (with circumvention plans)
  6. Assumption Documentation (with confidence ratings)
  7. Information Gap Analysis (research until 90%+ confidence)
  8. Ambiguity Elimination (resolve all vague language)

**Scenario B (User has vague idea):**
- Rigorously interrogate user across 6 categories
- Iterative deepening until high-level overview confirmed
- Then transition to Scenario A protocol

**Confirmation Gate:**
```
Based on your answers and my analysis, I understand:
- Goal: [summary]
- Scope: [summary]
- Success: [summary]
- Resources: [summary]
- Constraints: [summary]
- Assumptions: [summary]
- Information Gaps: [summary]

I will not truncate the project plan or any part of its files or instructions.

Is this correct? (Respond YES to proceed)
```

**DO NOT PROCEED until explicit YES.**

### Phase 4: Exegesis Section Creation

Read `references/phase4-exegesis.md`.

**CRITICAL: Exegesis describes WHAT and WHY, never HOW.**

Create:
- `intent-narrative.md` - Vision (300+ words), Purpose (150+ words), Design Philosophy, End State, Scope, Success Criteria
- `objectives.md` - Primary (min 5), Secondary (min 3), Non-Objectives
- `requirements.md` - Functional (min 10), Non-Functional (min 5), Integration, Technology

### Phase 5: Blueprint Section Creation

Read `references/phase5-blueprint.md`.

Create:
- `architecture.md` - Components, layers, patterns, diagrams
- `tech-stack.md` - Technologies with justification
- `interconnections.md` - Data flows, API contracts, events

### Phase 6: Implementation Section Creation

Read `references/phase6-implementation.md`.

**THIS IS WHERE MOST PLANS FAIL.**

Create ONE feature spec per feature (min 20+ for complex projects).

Each feature spec MUST contain:
- Purpose
- What to Build (NOT how)
- Core Components
- Functionality
- Integration Points
- UI (if applicable)
- Data Model (if applicable)
- Success Criteria (min 5)
- Dependencies
- Test Requirements (min 10)

### Phase 7: Task Matrix Creation

Read `references/phase7-task-matrix.md`.

Create:
- `wbs-full-tree.md` - 100+ tasks, hierarchical
- `linear-micro-plan.md` - 1000+ atomic actions, dependency order

### Phase 8: Instruction Files Creation

Read `references/phase8-instructions.md`.

**CRITICAL STEP - Most plans miss this.**

For EVERY plan file, create corresponding `.md.instructions` file.

Include test-first implementation protocol for ALL implementation files:
1. READ instruction file
2. READ plan file
3. CREATE TESTS FIRST
4. VERIFY TESTS FAIL
5. IMPLEMENT step by step
6. RUN TESTS after each step
7. FIX IMPLEMENTATION only
8. VERIFY ALL PASS
9. Document in completion-log.md
10. Git commit
11. Proceed to next file

### Phase 9: Milestones Section Creation

Read `references/phase9-milestones.md`.

Create `success-criteria.md` with min 20 success criteria.

Format:
```
## SC-[N]: [Feature/Area Name]
**Criteria**: [What must be true]
**Verification Steps**: [Numbered steps]
**Pass**: [Condition for passing]
**Fail**: [Condition for failing]
**Owner**: [Role responsible]
```

### Phase 10: Decisions Section Creation

Read `references/phase10-decisions.md`.

Create `decision-log.md` with min 10 decisions.

Format:
```
## [ID]: [Decision Name]
**Decision**: [What was decided]
**Rationale**: [Why this choice]
**Alternatives Considered**: [Other options]
**Consequences**: [Trade-offs]
**Date**: [When decided]
**Status**: [Proposed/Accepted/Superseded]
```

### Phase 11: Master Execution Documents Creation

Read `references/phase11-master-docs.md`.

Create:
- `MASTER-EXECUTION-INSTRUCTIONS.md` - Single entry point
- `EXECUTION-CHECKLIST.md` - Step-by-step checklist
- `AI-AGENT-START-PROMPT.md` - Self-contained agent prompt

### Phase 12: AI Agent Start Prompt Creation

Content defined in Phase 11. Ensure AI-AGENT-START-PROMPT.md is complete.

### Phase 13: Validation Loop (MANDATORY)

Read `references/phase13-validation.md`.

Validate ALL:

**Completeness:**
- All directories created
- All files created
- All instruction files created
- WBS has 100+ tasks
- Linear plan has 1000+ actions
- Min 20 feature specs
- Min 10 functional requirements
- Min 5 non-functional requirements
- Min 5 primary objectives
- Min 3 secondary objectives
- Min 20 success criteria
- Min 10 decisions

**Detail:**
- Feature specs describe WHAT not HOW
- Instruction files describe HOW
- Implementation instructions include test-first
- Test files specify 20+ tests
- WBS leaf tasks completable in hours
- Linear plan actions are single commands

**Consistency:**
- No contradictions
- Dependencies consistent
- Technology choices consistent
- Integration points match
- Success criteria match objectives

**Executability:**
- Agent can start at file 1
- All commands exact and runnable
- All paths absolute and correct
- All test files creatable from specs

**IF ANY CHECK FAILS, REVISE UNTIL ALL PASS.**

### Phase 14: Final Output Generation

Present:
- Summary (total files, specs, tests, actions)
- Complete directory tree
- Execution order
- Next steps
